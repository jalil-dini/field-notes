# 07 · A harness that fixes its own guards

**Paper:** [Self-Harness: Harnesses That Improve Themselves](https://arxiv.org/abs/2606.09498) (Zhang et al., 2026). Related:
[Evolving Agents in the Dark](https://arxiv.org/abs/2606.05922) (Pan et al., 2026) and [Beyond Prompts](https://arxiv.org/abs/2609.05736) (Zhao et al., 2026).

Those papers improve an agent without retraining the model: mine its failures, propose a small edit to the harness
around it, and keep the edit only if it passes a regression test. I ran that loop by hand on a real agent of mine: a
web agent that fills in free-sample and sticker request forms. Before it types anything, it asks a typed decision model
(Jev) five yes/no questions about the page, and skips it if any guard fires (sweepstakes, a cause or campaign,
businesses only, outside my area, or not a free offer at all).

## Setup

- **48 real pages**, captured once by the agent's probe mode, which runs the guards and stops before filling anything.
  Nothing was filled or submitted for this experiment. 14 free offers, 14 pages that are not offers (contact forms,
  report samples, mail-in requests), 10 sweepstakes, 5 businesses- or members-only, 3 outside my area, 2 causes.
- **Labels are mine**, written after reading each page. `why` explains the non-obvious ones.
- **Split** 28 tune / 20 held-out, stratified by label with a fixed seed. Fixes were written from tune failures only;
  the held-out pages were scored once, at the end.
- **Acceptance rule:** an edit is kept only if no tune page gets worse. The error that matters most is *filling a page
  that should be skipped*.

## The loop

| Version | Edit to the "is this a free offer?" question | Tune: right calls | Tune: wrong fills | Kept? |
|---|---|---|---|---|
| v0 | (as shipped) | 27/28 | 1 | baseline |
| v1a | Must be requested through a form here; mail, email or a newsletter-only form is no | 27/28 | 0 | no: broke a real sign-up offer (#25) |
| v1b | Samples of paid reports, quotes and consultations don't count | 27/28 | 1 | no: no gain |
| v2a | Mail or email requests are no; **a sign-up form that sends the item counts** | **28/28** | **0** | **yes** |
| v2 | v2a + v1b | 28/28 | 0 | no: no gain over v2a, so the smaller edit wins |

## Result on the held-out pages

| | Right calls | Filled a page it should skip | Skipped a real offer |
|---|---|---|---|
| v0 (shipped) | 18/20 | 2 | 0 |
| v2a (fixed) | 19/20 | 1 | 0 |

Across all 48 pages, wrong fills went from 3 to 1 and no real offer was lost. The fix came from one tune page (stickers
requested by mailing an envelope) and also fixed an unseen held-out page with the same problem. The remaining error is
a different failure: a sticker you only get after contributing to the site. No tune page showed that pattern, so the
loop could not find it. That is the method's limit, not a bug.

**Caveats.** 48 pages is small: one page is 2 to 5 points. The edits were written by me (with Claude), not
generated by the agent itself as in the paper; what is automatic here is the scoring and the accept-or-reject rule.
The home city in `guards_v0.json` is written as Orlando rather than the agent's real one.

## Run it

```bash
python3 score_guards.py guards_v0.json guards_v2a.json     # needs JEV_API_KEY
```

Scores are cached in `.jev_cache.json` (not committed), so a re-run with the same pages and questions costs nothing.
`results.json` holds every page's scores and decision for the last run.
